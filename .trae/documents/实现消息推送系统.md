# 消息推送系统实现计划

## 功能需求
- **服务端**：在客户端监控界面添加消息发送功能，支持单选、多选和全选客户端
- **客户端**：在通知按钮处显示未读消息，点击查看消息列表，支持离线消息存储

## 实现步骤

### 1. 服务端修改 (`main.py`)

#### 1.1 客户端监控界面增强
- 在 `ClientMonitorWidget` 类中添加：
  - 全选按钮
  - 消息输入区域（标题输入框、内容文本框）
  - 发送消息按钮
  - 消息发送状态提示

#### 1.2 消息存储系统
- 创建 `messages.json` 文件存储消息
- 实现消息管理功能（存储、查询、标记已读）

#### 1.3 API 接口扩展
- 在 `Server.py` 中添加消息相关接口：
  - `POST /api/v1/messages/send` - 发送消息
  - `GET /api/v1/messages/unread` - 获取未读消息
  - `POST /api/v1/messages/read` - 标记消息已读

### 2. 客户端修改 (`demo.py`)

#### 2.1 通知系统增强
- 修改 `CustomTitleBar` 类：
  - 添加未读消息计数器（显示在通知按钮上）
  - 实现消息列表界面
  - 修改 `_onNotificationClicked` 方法显示消息列表

#### 2.2 消息接收系统
- 添加消息接收和存储功能
- 实现定期检查未读消息的定时器
- 支持离线消息存储和上线后自动加载

### 3. 数据结构设计

#### 3.1 消息存储结构 (`messages.json`)
```json
{
  "client_id": {
    "messages": [
      {
        "id": "unique_id",
        "title": "消息标题",
        "content": "消息内容",
        "time": "2026-01-28 12:00:00",
        "read": false
      }
    ]
  }
}
```

#### 3.2 客户端记录增强 (`client_records.json`)
- 为每个客户端添加唯一 `client_id` 字段

### 4. 技术实现要点

#### 4.1 服务端
- 使用 `QTimer` 定期检查消息状态
- 实现消息发送确认机制
- 支持批量消息处理

#### 4.2 客户端
- 使用 `InfoBar` 显示新消息通知
- 实现消息列表的分页和筛选
- 支持消息标记已读和删除

#### 4.3 网络通信
- 客户端定期请求未读消息
- 服务端响应消息查询
- 支持离线消息存储和同步

## 预期效果
- 服务端可以向任意客户端发送消息，支持全选操作
- 客户端在通知按钮处显示未读消息数量
- 点击通知按钮查看完整消息列表
- 离线客户端上线后自动接收未读消息
- 消息状态（已读/未读）在服务端和客户端保持同步
